# Component Inventory

Source of truth for every reusable component in this prototype. Check here before building anything new — if it exists, reference it by name; never recreate a near-duplicate.

Audited 2026-07-30: all 58 screens under `src/app/components/*Screen.tsx` and all 20 non-screen files under `src/app/components/` were read in full, cross-referenced against `src/app/App.tsx` (the 8,300-line top-level nav switch, keyed on a single numeric `step` state).

**Known gap (flagged 2026-07-31, not yet closed):** this audit treated components defined *inline inside* `App.tsx` (~46 functions — the Dashboard variants, `SignInScreen`, `PasswordScreen`, `PhotoUploadScreen`, etc.) as incidental call-sites of the shared components above, not as first-class inventory. That's why the Dashboard variants' duplication showed up in passing (the `DrumWaveFooter`/`CompanyLogos`/`ProfileHalo` rows all list the same 4 call sites) but was never added to the "Known near-duplicate screens" list below — until the entry added today. Until a full pass audits all ~46 inline components the same way the 58 split screens were audited, treat every inline `App.tsx` component as un-vetted for duplication: flag before consolidating or deleting any of them, the same as a listed screen.

## How to use
- On first audit of the existing 60%, populate this table from what's already built.
- Add every new component immediately after building it — don't defer "I'll log it later."
- Where a Figma Code Connect mapping exists for a component, note it in the Notes column so it's clear the mapping (not this file) is the live source for that one.
